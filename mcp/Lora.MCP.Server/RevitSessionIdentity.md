# Revit-side session identity

The separately deployable pyRevit extension is located under `revit_identity/LoraIdentity.extension`. It registers `GET /lora-identity-v1/session_identity` on pyRevit's existing Routes server only when that server is bound exactly to `127.0.0.1`; otherwise startup refuses to register the route. It does not start another HTTP listener or modify RevitMCP.

## Identity model

The provider runs inside Revit's pyRevit process. At provider startup, it creates random `process_session_id` and `application_session_id` UUIDs. Each open Revit `Document` object receives a new random `document_session_id`. That document token is independent of title, path, element IDs, or PID. The record also contains the Revit PID, title/path when available, project/family type, Revit version number, lifecycle sequence/generation, active-document switch counter, and provider version.

Multiple open documents have independent tokens, including a project and family with the same title. Closing removes the tracked .NET document reference after Revit's `DocumentClosed` event. Opening or reopening the same file creates a new object and token. Unsaved documents and family documents are supported and may have no path. If the active document is missing, closing, not in Revit's open-document collection, or Revit is shutting down, the route returns an error and no identity token.

## Lifecycle events

The sidecar subscribes once to `Application.DocumentOpened`, `Application.DocumentClosing`, `Application.DocumentClosed`, `UIApplication.ViewActivated`, and `UIApplication.ApplicationClosing`. Open and close events reconcile the small `Application.Documents` collection with `Document.Equals`, with object-reference identity as a fast path. It does not use title/path equality. Revit documents that `Document.Equals` compares wrappers representing the same currently open document; a newly opened lifecycle therefore receives a distinct session. The view activation event updates the active document session counter; view changes within the same document do not increment it. Closing increments a lifecycle generation immediately so an in-flight before/after check is invalidated even if Revit later cancels that close. The runtime is retained in pyRevit's session-scoped environment store to avoid duplicate event handlers on extension reload. An explicit subscription tracker also prevents duplicate event-name subscriptions. Shutdown unsubscribes all retained event handlers, clears document references, and removes the session runtime entry.

## `active_document_changed` diagnosis

The Route handler receives `doc` from Routes' prepared handler context, while the identity provider independently reads `uiapp.ActiveUIDocument.Document`. The earlier implementation compared these two .NET wrapper objects only with `System.Object.ReferenceEquals`. Revit can expose different CLR wrappers for the same live `Document`, so reference inequality was incorrectly treated as an active-document switch. The same overly strict comparison in the registry could also split a session when `Application.Documents` or `ViewActivated` exposed another wrapper. The provider now uses `Document.Equals` for these identity checks and continues to fail closed if equality cannot be established or the document is not in the current open-document collection.

Identity responses now include safe diagnostics: booleans for wrapper-reference equality, Revit document equality, title/path match, open-list membership, and object validity; event handler/subscription counts; event counters; and a failure reason. These values do not include session tokens or the actual title/path values. A normal view activation for another view in the same document must report `same_revit_document: true` and preserve the document token. A real document switch, null active document, or missing open-document membership still returns an error without identity. The diagnostics are observations of the query; event counts can change between individual reads if Revit raises an event during the request.

Revit 2024's installed `RevitAPI.xml` documents the open/close event members and their event argument behavior; the API event references identify the relevant lifecycle events as longstanding APIs. Autodesk's current API reference documents [DocumentOpened](https://help.autodesk.com/cloudhelp/2026/ENU/Revit-API-MainReference/files/html/b9415c2d-442e-f61d-aafa-de31cce7959b.htm), [DocumentClosed](https://help.autodesk.com/cloudhelp/2026/ENU/Revit-API-MainReference/files/html/d6c0ea53-175c-75b5-4e0e-9b3d5ba92f06.htm), [ViewActivated](https://help.autodesk.com/cloudhelp/2026/ENU/Revit-API-MainReference/files/html/b208aae7-5cbf-21b4-b70e-af2e63ece383.htm), and [UI event guidance](https://help.autodesk.com/cloudhelp/2024/ENU/Revit-API/files/Revit_API_Developers_Guide/Advanced_Topics/Events/Revit_API_Revit_API_Developers_Guide_Advanced_Topics_Events_User_Inteface_Events_html.html).

## Lora client and guard

Lora reads the session route only at the already selected loopback Routes port. It checks the returned Revit PID, active title, and available path against the existing diagnostics route. Session ID, process/application tokens, lifecycle generation, active-switch counter, provider version, and endpoint are included in before/after identity comparisons. An HTTP 404 or pyRevit's specific `RouteHandlerNotDefinedException` response means the sidecar is not installed and is reported explicitly; other provider failures reject identity retrieval rather than falling back. The old title/path/PID composite remains informational only and cannot make the guard safe.

`ReadOnlyDocumentGuard` now requires a ready provider and nonempty process, application, and document session tokens that match the document identifier. It rejects missing, stale, changed, or uncertain sessions. No write operation is implemented. Future guarded operations must call identity verification immediately before and after the operation.

## Compatibility and verification

The sidecar targets Revit 2023–2026 and uses the pyRevit `framework.EventHandler` adapter to subscribe to Revit API events, avoiding direct assumptions about IronPython versus CPython event delegate conversion. Revit 2024 event API metadata has been inspected; this is metadata/source evidence only. No current-source host runtime test has been performed for any target version. The Revit 2023 API assembly was unavailable in the reviewed environment, and Revit 2025/2026 assemblies were not available there. Automated lifecycle tests use fake document references and do not run inside Revit. Revit 2025/2026 also use a different .NET runtime generation from 2023/2024, so the event adapter requires host testing in those releases.

Before any controlled deployment test, use a disposable Revit installation and model, preserve the original sidecar, and define rollback. Fully exit and restart Revit after a test update so old event delegates/runtime state are discarded. Confirm the route reports `same_revit_document: true` even if `captured_document_reference_equal` is false, and that repeated GETs keep the same document-session identity. Test view changes, document switching, close/reopen, and a temporary no-document state. Restore the test backup and restart Revit to roll back. No target version is runtime-verified.

## Security

The sidecar refuses to register when the Routes service is bound to a wildcard or non-loopback host. It does not configure the listener or firewall. No authentication is implemented because Routes provides no auth middleware and does not pass request headers to route handlers; a bearer token in a URL is not safe. Loopback binding limits network exposure but does not authenticate other local processes. Verify actual listener ownership/binding and firewall policy in the intended test environment. See [RevitIdentityDeployment.md](RevitIdentityDeployment.md) for the readiness gate.
