# Lora read-only MCP tools

All tools are explicitly registered in `lora_mcp/server.py`. There is no generic route or arbitrary RevitMCP tool execution tool.

| Tool | Input schema | Output and source | Limitations |
|---|---|---|---|
| `lora_get_project_info` | None | Project name, number, project status, active document title/path/process ID, Revit version availability; `GET /project_info` with diagnostics identity checks | Route does not provide Revit application/API version; version is returned as unavailable/null. |
| `lora_get_levels` | `offset: int=0`, `limit: int=200` (max 200) | All level records from `POST /model/statistics`; adds mm using internal feet × 304.8 and preserves original feet | No dedicated levels route. Completeness compares returned level count with upstream total. |
| `lora_get_level_catalog` | `offset: int=0`, `limit: int=100`, `failure_offset: int=0`, `failure_limit: int=50` (each page max 100) | Identity-guarded read-only sidecar Level instance IDs, names, internal-foot elevations and millimetre conversions; element and field-failure pagination are independent | Does not modify Revit. Complete inventory is required before generation planning treats the Level ID catalog as globally complete. It does not verify shared coordinates or clearance. |
| `lora_get_views` | `offset: int=0`, `limit: int=60` (max 200) | View ID/name/type, placement and sheet fields from `GET /sheets/list_views` | Upstream returns only non-template, non-sheet views; route itself is not paged, so response cap can reject a large payload. |
| `lora_get_elements` | Required `category: str`; optional `level: str=""`, `filters: list=[]`, `offset: int=0`, `limit: int=40` (max 100), `include_parameters: bool=false` | IDs from `POST /get_elements_by_category` or `/elements/filter`; optional basic property enrichment via `/elements/get_properties`; `complete`, `has_more`, and upstream count agreement | Upstream returns the full matching ID list, without server-side pagination. Completeness is false if upstream `count` disagrees with returned IDs. |
| `lora_get_element_parameters` | Required `element_ids: list` (max 500); optional `parameter_names: list` (max 100), `offset: int=0`, `limit: int=40` (max 100) | Parameter values, storage type, `has_value`, numeric metadata and normalized value status from `POST /elements/get_properties` | RevitMCP merges type values with instance values without source markers; read-only metadata is not returned. Missing vs unavailable can be indistinguishable for names requested from upstream. |
| `lora_analyze_model` | `top_n: int=200` (1–200), `include_levels: bool=true` | Summary, category counts, optional levels from `POST /model/statistics`; reports category/level completeness | RevitMCP caps `top_n` at 200. Results are marked incomplete when upstream reports truncation. |
| `lora_get_bim_context` | `view_offset: int=0`, `view_limit: int=60`; optional `category: str`, `parameter_names: list[str]`; `element_offset: int=0`, `element_limit: int=20`, `top_n: int=200` | Composes project, levels, views, statistics, and an optional element/parameter page using the six base tool functions | This is an overview/context page, not an exhaustive parameter audit. `complete` and per-section completeness fields identify partial views/elements. |
| `lora_answer_bim_question` | Required `question: str` (1–500 chars); `max_pages: int=20` (1–100) | Answers supported natural-language queries from the six base functions; category-inventory questions request one bounded `lora_get_category_inventory` page; selected-geometry queries call `lora_get_element_geometry` only when explicit numeric element IDs are present (max 25); lists or recommends verified Lora commands | Deterministic intent matching, not an LLM. Geometry is never scanned model-wide; clearance remains unverified. Paged results stay incomplete when max pages/upstream values do not cover the full result. Command effects and limitations are reported; recommendations never execute commands. |
| `lora_list_commands` | None | Returns all 12 source-verified descriptive ribbon-command records from `lora_context/registry.py`, including required inputs, supported context, limitations, and model effects | Static repository metadata only; does not query Revit or execute ribbon commands. The registry is source-inspected, not a claim of runtime validation. |
| `lora_inspect_drawing` | Required `file_name`; optional `dpi=100`, `run_ocr=false`, `max_dimension=3000` | Detects/inspects PDF, JPG/JPEG, PNG, or reports DWG as unsupported | Filename only inside `drawing_inbox` (or `LORA_DRAWING_INBOX`); no arbitrary filesystem paths. DWG is signature-recognized but not parsed. |
| `lora_process_pdf` | Required `file_name`; `dpi=100` (36–300), `run_ocr=false` | Metadata, page count/dimensions/rotation, embedded text/bboxes, bounded vector geometry and in-memory page renders | OCR is opt-in and runs only for low-text pages; Tesseract was unavailable in the development environment and OCR is unverified. Render image content is retrieved separately via `lora_get_drawing_render`. |
| `lora_process_image` | Required `file_name`; `max_dimension=3000` (256–5000), `run_ocr=false` | Original image metadata, EXIF orientation transform, resize info, OCR status, edge count and line segments | Uses processed-pixel coordinates. Tesseract was unavailable in the development environment; image source scale is not inferred. |
| `lora_get_drawing_summary` | Required `processing_id` | Retrieves a prior drawing result from a 20-entry process-local cache | Cache is lost at process exit or eviction. No drawing content is written to disk. |
| `lora_get_drawing_render` | Required `processing_id`; `page_number: int=1` | Returns a cached rendered page or prepared raster as MCP image content | Process-memory cache only; 8 MiB/page and 32 MiB total. Evicted or oversized images are unavailable. Never accepts file paths. |
| `lora_extract_drawing_geometry` | Required `file_name`; optional `dpi=100`, `max_dimension=3000` | Bounded PDF vector/text entities or raster lines/components/contours plus coordinate metadata | Input is filename-only from configured inbox. Native DWG extraction is unsupported. |
| `lora_analyze_drawing_geometry` | `processing_id`; optional `page_number`; tolerances and `max_pairs` | Parallel/perpendicular, intersection, endpoint proximity, grouping and completeness analysis | Distance tolerances are in source coordinates; pair checks and returned relationships are capped. |
| `lora_get_architectural_candidates` | `processing_id`; optional `page_number` | Wall-like, opening, junction, room-boundary and dimension-line candidate hypotheses | Every result is unconfirmed and includes evidence/warnings; heuristics can produce false positives. |
| `lora_recognize_architecture` | Required `processing_id`; optional `page_number` | Deterministic architectural hypotheses over a previously processed drawing; stores result in bounded process memory | Not an AI provider; no confirmed BIM classification, no calibration, OCR depends on processing-time availability. |
| `lora_get_recognized_elements` | Required `recognition_id`; optional `category`, `page_number`, `offset=0`, `limit=100` (max 500) | Paged recognition hypotheses with source references and warnings | Cache expires on restart/eviction; category matching is exact case-insensitive. |
| `lora_analyze_recognition` | Required `recognition_id` | Counts hypotheses by category and review status, including OCR/provider/calibration availability | Summary only; consult completeness and warnings for limitations. |
| `lora_get_recognition_warnings` | Required `recognition_id` | Global and per-page completeness, OCR status and warnings | Same process-local result lifetime. |
| `lora_calibrate_drawing` | Required `processing_id`, `recognition_id`; page; optional explicit scale, verified dimension references, origin, rotation, target unit, independent axes, and shared-point references | Page-local affine calibration and transformed recognized geometry; caches result | Only user-confirmed references determine scale. Inconsistent values are flagged; no automatic sheet combination. |
| `lora_get_calibration_result` | Required `calibration_id` | Retrieves complete calibration parameters and warnings | Bounded process-local cache. |
| `lora_get_reconstructed_spatial_geometry` | Required `calibration_id`; optional category, offset, limit (max 500) | Paged calibrated-coordinate hypotheses | Requires a transform; uncalibrated result has no reconstructed geometry. |
| `lora_validate_calibration_references` | Required `processing_id`, `recognition_id`; page and reference list | Checks reference shape, extracted segment correspondence and optional recognized text ID association | Geometry match does not verify the real-world truth of a dimension; OCR needs user confirmation. |
| `lora_create_drawing_review` | Required `recognition_id`; optional `calibration_ids`, `title`, `reviewer` | Creates a versioned persistent review session and pending item snapshots | Stores no original drawing bytes; source render cache remains process-local. |
| `lora_get_drawing_review` | Required `review_id` | Returns session, status summary, page numbers and existing render tool pointer | Render must still be present in the drawing process cache. |
| `lora_get_review_items` | Required `review_id`; optional status/category/page/offset/limit (max 500) | Paged persistent items and source/calibrated overlays | All items begin pending; no automatic approval. |
| `lora_get_review_item` | Required `review_id`, `item_id` | Returns original/current geometry, properties, evidence and item history | Corrections remain separate from original snapshots. |
| `lora_update_review_item` | Required review/item IDs; optional properties, geometry, status, reviewer, reason | Validated property/geometry correction or pending/needs_correction/unresolved transition | Cannot set approved/rejected; uses a strict property and geometry schema. |
| `lora_approve_review_item` | Required review/item IDs; optional reviewer/reason | Explicitly changes status to approved | Stale calibration blocks approval; missing/incomplete calibration is warned and excluded from ready count. |
| `lora_reject_review_item` | Required review/item IDs and reason; optional reviewer | Explicitly rejects an item | A rejected item must return to pending before approval. |
| `lora_get_review_history` | Required `review_id`; optional `item_id`, offset, limit | Returns persistent audit events | Reviewer identity is caller-provided, not authenticated by this local server. |
| `lora_get_review_summary` | Required `review_id` | Counts by status/category and calibration readiness | Summary is based on persistent review records, not Revit. |
| `lora_validate_drawing_review` | Required `review_id`; optional current `calibration_ids` | Compares calibration fingerprints and persists stale flags/history | No supplied current calibration means no change is assumed but comparison is reported unavailable. |
| `lora_create_generation_plan` | Required `review_id`; optional per-item `mappings`, user-confirmed `coordinate_mapping` | Builds and persists a plan from approved/currently calibrated items, using read-only project, diagnostics, statistics, family-symbol and schema routes | Plan creation is local data only. Unapproved/stale items are unresolved; no Revit operation is executed. |
| `lora_get_generation_plan` | Required `plan_id` | Returns persisted plan and mapping/revalidation history | Local persistence only; no Revit request. |
| `lora_validate_generation_plan` | Required `plan_id` | Revalidates document identity, levels, available types, geometry and dependencies using read-only routes | Catalogs/IDs may be incomplete; validation is not execution authorization. |
| `lora_get_generation_plan_items` | Required `plan_id`; optional category/status/offset/limit (max 500) | Returns bounded plan item page and unresolved source items | Local persistence only. |
| `lora_update_generation_mapping` | Required plan/item IDs and `mapping` object | Persists explicit type/level/host/parameter mapping and an audit event; validates against read-only inventory | Changes only local plan data. No arbitrary type selection or Revit writes. |
| `lora_get_generation_plan_summary` | Required `plan_id` | Counts plan states, validation errors/warnings and unresolved items | Read-only local persistence. `ready_for_review` does not imply executable support. |
| `lora_create_generation_preview` | Required `plan_id` | Persists an element-level preview and classified validation results; reads live Revit inventory when available | If RevitMCP is unavailable, preview remains explicitly unverified and blocked; no execution is possible. |
| `lora_get_generation_preview` | Required `preview_id` | Retrieves a stable snapshot and marks it stale if its source plan version changed | Local persistence only; original drawing bytes are not stored. |
| `lora_get_generation_preview_items` | Required `preview_id`; optional category/status/offset/limit (max 500) | Returns bounded proposed elements and validation data | Visual data is structured 2D; no native Revit 3D preview. |
| `lora_validate_generation_preview` | Required `preview_id` | Creates a new snapshot using current read-only inventory and preserves the prior snapshot | Existing snapshot becomes stale; inventory source and verification time are explicit. |
| `lora_get_generation_preview_summary` | Required `preview_id` | Summarizes counts, errors, warnings, information and live verification | `ready_for_execution` is always false in this milestone. |
| `lora_compare_generation_previews` | Required `first_preview_id`, `second_preview_id` | Compares stable snapshots by source item, mapping, geometry, dependencies and validation | No Revit request. |

Every Revit route call is bracketed by active document diagnostics and the optional Revit-side session route. Calls fail with `document_changed` if title, path, document type/version, process ID, session IDs, lifecycle generation, active-document switch counter, or endpoint changes during the operation. The guard rejects uncertain identity; title/path/PID composites are never accepted as a substitute for the session provider. `lora_get_project_info` reports the `ProjectInformation.Status` value as `status_value` to distinguish it from MCP call status. See [RevitConnection.md](RevitConnection.md) and [RevitSessionIdentity.md](RevitSessionIdentity.md) for connection evidence and identity-provider limitations.

## Error envelope

```json
{"status":"error","error":{"code":"timeout","message":"Timed out communicating with RevitMCP"}}
```

Errors use stable codes for validation, discovery/connection, HTTP errors, invalid/oversized JSON, missing document, and document identity changes. Sensitive parameter payloads are not logged.

See [BIMContext.md](BIMContext.md) for context shape and [AIReasoning.md](AIReasoning.md) for supported natural-language query behavior.

Drawing tool safety bounds, dependencies, output shape and format limitations are documented in [DrawingProcessing.md](DrawingProcessing.md), [DrawingFormats.md](DrawingFormats.md) and [CoordinateSystems.md](CoordinateSystems.md).
Geometry entities, tolerances, candidate methods and safe render retrieval are documented in [DrawingGeometry.md](DrawingGeometry.md).
Generation plan fields, type/level mapping, validation and execution limitations are documented in [GenerationPlanning.md](GenerationPlanning.md).

## Revit-side coordinate and geometry diagnostics

| Tool | Input | Output and safety |
|---|---|---|
| `lora_get_wall_types` | None | Actual `WallType` inventory from the loopback Lora sidecar; read-only. |
| `lora_get_coordinate_diagnostic` | None | Internal Origin, Project Base Point, Survey Point, active ProjectLocation, transform and guarded coordinate cross-checks; read-only. |
| `lora_get_geometry_inventory` | `offset: int=0`, `limit: int=50`, `failure_offset: int=0`, `failure_limit: int=50` (each max 100) | Bounded element page and independent failure page, with a consistent per-element status schema and full-scan counters. Loaded links are scanned in link-document coordinates; no host-space clash test is performed and clearance is always `unverified`. |
| `lora_get_category_inventory` | Optional `discipline` (`architecture`, `structural`, `mep`, `other`, `unknown`) and `category_id`; independent `offset`/`limit`, `failure_offset`/`failure_limit`, and `category_offset`/`category_limit` (all max 100) | Category counts use `BuiltInCategory` identifiers, separately report instance and type counts, and return bounded instance details. The details page reads type/level, Location and bounding-box evidence only. Category membership and coarse geometry do not prove physical clearance; links are not traversed. |
| `lora_get_element_geometry` | Required `element_ids` (1–25 unique numeric IDs); optional `entity_offset=0`, `entity_limit=100` (max 200) | Bounded solid/mesh/face/edge/curve descriptors and instance-transform provenance for explicitly requested elements. Geometry entities have a global cap of 200 and nesting is capped at depth 8. Links are not traversed; there is no clash or clearance computation. |

See [CoordinateGeometryDiagnostic.md](CoordinateGeometryDiagnostic.md) for coordinate semantics, API limitations, pagination and completeness behavior.
